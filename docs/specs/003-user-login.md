# 003: Google 로그인

## 목적

사용자가 별도의 회원가입 양식을 작성하지 않고 Google 계정으로 로그인한다. 로그인한 사용자는 이후 자신의 사주 해석 결과를 계정에 연결해 여러 방문에서 다시 볼 수 있다.

## 결정된 내용

- 로그인은 **Supabase Auth의 Google OAuth**를 사용한다. OAuth는 Google이 본인 확인을 하고, 서비스에는 로그인 결과만 돌려주는 방식이다.
- 화면에는 `Google로 로그인` 버튼 하나를 제공한다. 이메일·비밀번호 회원가입, 비밀번호 찾기, 다른 소셜 로그인은 만들지 않는다.
- 첫 Google 로그인 때 Supabase 내부에는 사용자 계정이 자동으로 만들어질 수 있지만, 사용자가 별도의 회원가입 양식을 작성하지는 않는다.
- 로그인하지 않은 사용자도 현재의 사주 계산과 화면 확인을 계속 사용할 수 있다. 계정에 결과를 저장하거나 불러오는 기능만 로그인이 필요하다.
- 브라우저가 로그인 상태를 안전한 세션으로 유지한다. Google 비밀번호와 Google 액세스 토큰을 앱의 코드, `localStorage`, URL, Git에 저장하지 않는다.
- Supabase 연결에는 기존 환경변수 `NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 사용한다. 서버 관리 권한을 가진 키는 브라우저에 넣지 않는다.

## 사용자 흐름

1. 로그인하지 않은 사용자는 화면 위쪽의 `Google로 로그인` 버튼을 누른다.
2. 서비스는 사용자를 Google 로그인·동의 화면으로 보낸다.
3. 사용자가 Google에서 로그인을 마치면 서비스의 인증 콜백 주소로 돌아온다.
4. 서버가 일회용 인증 코드를 로그인 세션으로 교환한 뒤 원래 서비스 화면으로 보낸다.
5. 화면에는 로그인한 사용자의 이름 또는 이메일과 `로그아웃` 버튼이 보인다.
6. 새로고침하거나 브라우저를 다시 열어도 유효한 세션이면 로그인 상태를 복원한다.
7. 로그아웃하면 세션을 끝내고 로그인 버튼을 다시 보여준다. 다른 사용자의 계정 데이터는 화면에 남기지 않는다.

## 화면과 문구

- 로그아웃 상태: `Google로 로그인` 버튼을 보여준다.
- 로그인 처리 중: 버튼을 다시 누를 수 없게 하고 `로그인하고 있습니다…`라고 알린다.
- 로그인 상태: Google에서 받은 표시 이름이나 이메일 중 사용할 수 있는 값을 보여주고 `로그아웃` 버튼을 제공한다.
- 로그인 실패 또는 취소: `로그인을 완료하지 못했습니다. 다시 시도해주세요.`라는 쉬운 안내와 재시도 방법을 보여준다.
- 계정 저장이 필요한 동작을 로그아웃 상태에서 누르면 로그인 이유를 먼저 설명하고 로그인 버튼을 보여준다.

## 인증 콜백과 설정

- 로컬 개발 주소와 실제 배포 주소의 콜백 경로를 `/auth/callback`으로 통일한다.
- Supabase 대시보드의 Google 제공자 설정과 허용된 리디렉션 주소에 로컬 주소와 실제 배포 주소를 등록한다.
- 로그인 뒤에는 외부에서 전달된 임의의 주소로 이동하지 않는다. 서비스 안에서 허용한 상대 경로만 사용해 잘못된 사이트로 보내는 일을 막는다.
- 설정값이 없으면 로그인 버튼을 성공한 것처럼 동작시키지 않고 `로그인 설정이 아직 준비되지 않았습니다.`라고 안내한다.

## 개인정보와 보안

- 앱이 사용하는 기본 정보는 Supabase 사용자 ID, 표시 이름, 이메일, 프로필 이미지 주소로 제한한다. Google 연락처나 파일 접근 권한은 요청하지 않는다.
- 화면에서 사용자 식별이 필요할 때 이메일 전체를 불필요하게 반복 표시하지 않는다.
- 인증 여부는 브라우저가 보낸 값만 믿지 않고 Supabase가 확인한 서버 세션을 기준으로 판단한다.
- 데이터베이스에 저장할 사용자별 자료는 Supabase 사용자 ID로 구분하고, 본인 자료만 읽고 쓸 수 있도록 행 수준 보안 정책을 사용한다. 구체적인 저장 구조는 별도 Spec에서 정의한다.
- 로그와 오류 메시지에 세션 토큰, 인증 코드, 환경변수 값을 남기지 않는다.

## 실패와 예외

- 사용자가 Google 화면에서 취소하면 앱으로 돌아왔을 때 다시 로그인할 수 있다.
- 콜백 코드가 없거나 만료됐거나 올바르지 않으면 세션을 만들지 않고 실패 안내를 보여준다.
- Supabase 또는 네트워크가 일시적으로 실패하면 현재 사주 계산 결과는 유지하고 로그인만 다시 시도하게 한다.
- 세션이 만료되면 로그인 상태를 조용히 해제하고, 계정 저장이 필요한 시점에 다시 로그인하도록 안내한다.
- 로그아웃에 실패했을 때 로그인된 것처럼 화면만 먼저 바꾸지 않는다.

## 확인 기준

1. 로그아웃 상태에서 Google 로그인 버튼을 누르면 Google 로그인 화면으로 이동한다.
2. 정상 로그인을 마치면 서비스로 돌아오고 이름 또는 이메일과 로그아웃 버튼이 보인다.
3. 새로고침 뒤에도 유효한 세션이 유지된다.
4. 로그아웃하면 계정 정보가 사라지고 로그인 버튼이 다시 보인다.
5. 로그인 취소, 잘못된 콜백, 설정 누락, 네트워크 오류에서 비밀 정보 없이 이해하기 쉬운 안내를 보여준다.
6. 로그인하지 않은 사용자도 기존 사주 계산과 로컬 결과 확인을 사용할 수 있다.
7. 다른 사용자로 로그인했을 때 이전 사용자의 계정 데이터가 보이지 않는다.
8. 타입 검사, 자동 테스트, 실제 로컬 화면에서 성공·실패·로그아웃 흐름을 확인한다.

## 이번 Spec에서 제외

- 이메일·비밀번호 회원가입과 로그인, 비밀번호 찾기, 다른 소셜 로그인.
- 관리자 권한, 유료 회원 구분, 계정 설정 화면, 계정 삭제.
- 사주 해석 결과를 데이터베이스에 저장하고 목록으로 불러오는 기능. 이 기능은 별도 Spec으로 정의한다.

## 구현 전 준비

- Supabase 프로젝트에서 Google 로그인 제공자를 켜고 Google OAuth의 클라이언트 ID와 비밀값을 등록해야 한다.
- `.env`의 `NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`가 실제 프로젝트 값인지 확인해야 한다.
- 로컬 주소와 Vercel 배포 주소가 정해지면 각각의 콜백 주소를 Supabase 허용 목록에 등록해야 한다.

## 구현·검증 상태

- 2026-09-23: Supabase Auth 브라우저·서버 클라이언트, Google 로그인 버튼, `/auth/callback`, 세션 갱신, 로그인 상태 표시와 로그아웃을 구현함.
- Supabase 프로젝트에서 Google 제공자가 활성화된 것을 확인하고 `http://127.0.0.1:3000/auth/callback`을 허용된 리디렉션 주소에 추가함. 기존 `localhost` 주소도 유지함.
- 외부 주소와 백슬래시를 이용한 변형 주소를 로그인 뒤 이동 경로로 허용하지 않도록 검사함.
- `npm run check`에서 전체 자동 테스트 36개, 실패 0개. `npm run build` 통과. 로컬 화면에서 로그인 버튼과 설정 상태를 확인함.
- **남은 검증:** 참가자가 실제 Google 계정을 선택한 뒤 로그인 복원과 로그아웃을 확인해야 함. 개인 Google 계정 선택은 Codex가 대신 수행하지 않음.
