# 008: 로그인 사용자의 오늘의 운세

## 목적

로그인 사용자가 자신의 사주를 바탕으로 오늘의 운세를 매일 확인한다.

## 사용자가 확정한 요구사항

- Google 로그인 사용자만 오늘의 운세를 이용한다.
- Gemini가 매일 개인별 문장을 작성한다.
- 결과는 한 줄 요약, 일, 돈, 관계, 실천 팁으로 구성한다.

## 확정된 날짜·운영 기준

- 계정에 저장된 최근 정상 사주 결과 1개를 개인화 근거로 쓴다. 없으면 사주 입력과 계정 저장을 안내한다.
- `Asia/Seoul`의 자정부터 다음 자정 전까지를 같은 하루로 본다.
- 한국 시간 오전 8시대 예약 작업으로 그날 운세를 미리 만든다. 오전 9시까지 준비하는 것이 목표다. 예약이 실패하거나 이후 새 사주가 저장되면 버튼 요청에서 생성한다.
- 같은 날짜의 운세는 고정한다. 지난 운세는 보관하지 않고 사용자별 최신 결과 1개만 저장한다.
- 기존 `lib/saju`와 `lunar-javascript`로 오늘의 일진 및 사주와의 관계를 계산한다. Gemini는 계산값에 연결된 문장만 작성한다.
- 원본 출생 날짜·시각, 성별, 계정 정보는 Gemini에 보내지 않고 서버의 `GEMINI_API_KEY`를 쓴다. 기존 모델 `gemini-3.5-flash-lite`를 유지한다.
- 같은 날짜의 결과는 Supabase에 사용자별로 저장해 다시 방문하거나 다른 브라우저에서 열어도 동일하게 보여준다. 행 수준 보안으로 본인 결과만 접근하게 한다.
- 계정의 사주가 같은 날 바뀌면 새 사주를 기준으로 운세를 다시 만든다.

## 화면 흐름

Spec 009 적용 후 오늘의 운세는 로그인 사용자 상단 메뉴에서 여는 별도 페이지에 표시한다.

1. 로그인한 사용자에게 오늘 날짜와 운세 영역을 보여준다.
2. 사용자가 `오늘의 운세 보기`를 누르면 서버가 로그인과 저장된 사주를 확인한다.
3. 예약 작업이 미리 만든 운세가 있으면 다시 보여준다. 없으면 계산값을 바탕으로 Gemini에 요청한다.
4. 화면에서 오늘 일진 등 계산 근거와 Gemini의 해석을 구분해 보여준다.
5. 다음 날짜에는 새 날짜의 운세를 요청할 수 있다.

## 실패 조건

- 로그아웃 상태, 계정에 저장된 사주가 없음, 사주 자료 손상, 일진 계산 실패, Gemini 설정·호출·형식 오류, DB 저장 오류는 가짜 운세를 표시하지 않는다.
- 실패를 알기 쉬운 문장으로 안내하고 재시도를 제공한다. 이미 저장된 기존 사주 해석은 유지한다.
- 동일 날짜에 동시에 생성 요청이 오더라도 사용자에게 서로 다른 저장 결과가 표시되지 않아야 한다.

## 검증 기준

1. 비로그인 요청은 거절하고, 로그인해도 본인 사주와 운세만 조회한다.
2. 확정된 하루의 날짜 기준에 따라 같은 날짜의 운세를 재사용하고, 다음 날짜에는 별도 결과를 만든다.
3. 응답은 요약·일·돈·관계·실천 팁과 계산 근거가 모두 있는 경우에만 사용한다.
4. 잘못된 응답이나 호출·저장 실패는 성공으로 표시하지 않는다.
5. 원본 출생정보와 API 키가 Gemini 요청, 운세 저장 행, 브라우저 코드에 포함되지 않는다.
6. 관련 자동 테스트, 타입 검사, 빌드, 기존 사주 기능 회귀 검증을 수행한다.

## 배포 환경 준비

- Vercel 예약 작업은 UTC 기준 전날 23:00(한국 시간 오전 8시)에 등록한다. 무료 플랜에서는 같은 시각부터 한 시간 안에 실행될 수 있다.
- `CRON_SECRET`으로 예약 경로를 보호한다. `SUPABASE_SECRET_KEY`는 서버의 예약 작업이 계정별 저장 사주를 읽을 때만 사용한다.
- 비밀키가 없으면 예약 실행을 성공으로 표시하지 않는다. 버튼 생성은 사용자 세션의 행 수준 보안 권한을 사용한다.
