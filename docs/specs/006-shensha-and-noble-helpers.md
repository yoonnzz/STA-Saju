# 006: 개인별 살·귀인 전체 계산과 생활 해석

## 목적

사용자의 사주팔자에서 서비스 규칙집이 지원하는 살과 귀인을 모두 계산한다. 발견된 항목마다 삶에서 긍정적·어려운 방향으로 드러날 수 있는 조건, 현재 시기의 관련성, 생활 예시와 활용 행동을 쉬운 한국어로 설명한다.

## 사용자가 원하는 경험

- 사용자가 생년월일·출생시간·성별을 입력하면 자신의 사주에 해당하는 살·귀인을 확인한다.
- 임의로 대표 항목 몇 개만 고르지 않는다. 규칙집 43개를 모두 검사하고 발견된 항목을 전부 표시한다.
- 같은 살·귀인이 여러 기둥에서 발견되면 하나로 묶어 읽되, 발견 위치와 계산 근거는 모두 보여준다.
- 살을 불행으로, 귀인을 자동으로 찾아오는 행운으로 단정하지 않는다.
- 같은 상징이 어떤 환경과 행동에서는 강점으로, 다른 환경과 행동에서는 어려움으로 나타날 수 있는지 함께 읽는다.
- 타고난 사주의 조건과 현재 대운·올해·내년에서 같은 조건이 다시 나타나는지를 구분한다.

### 목록의 의미

- `전체`는 세상 모든 학파의 모든 이름을 뜻하지 않는다. 위에 공개한 `서비스 계산 기준 v1의 43개 전체`를 뜻한다.
- 이름이 다른데 같은 계산 조건을 쓰는 항목과, 같은 이름인데 계산표가 다른 항목을 구분해 기록한다.
- `도화·함지`, `학당·사관`, `고진·과숙`처럼 함께 묶인 항목은 화면에서 세부 이름과 각각의 적중 근거를 보존한다.
- 규칙집에 없는 이름을 Gemini가 추가하지 못하게 한다.

## 규칙집 데이터 구조

각 항목은 코드와 분리된 고정 규칙 데이터로 관리한다.

```ts
type ShenshaRule = {
  id: string;
  name: string;
  aliases: string[];
  group: "core" | "common" | "compound" | "inauspicious" | "extended";
  polarity: "helper" | "caution" | "mixed";
  anchors: ("yearStem" | "dayStem" | "yearBranch" | "dayBranch" | "monthBranch" | "dayPillar" | "nayin")[];
  scanTargets: ("year" | "month" | "day" | "hour")[];
  tableVersion: string;
  sourceStatus: "cross_checked" | "method_difference" | "partial";
  sourceNote: string;
};
```

- `sourceStatus`가 `method_difference`이면 다른 표가 존재한다는 안내를 결과에 표시한다.
- `partial` 항목도 계산은 하되 `이 서비스가 선택한 규칙`이라는 표시를 붙인다.
- 규칙 변경 시 `tableVersion`을 올리고 기존 저장 결과의 계산 버전을 유지한다.
- Gemini는 규칙표를 만들거나 수정하지 않는다.

## 계산 결과 구조

```ts
type ShenshaHit = {
  ruleId: string;
  name: string;
  group: string;
  polarity: "helper" | "caution" | "mixed";
  anchor: { pillar: string; value: string };
  target: { pillar: string; value: string };
  sourceStatus: string;
};

type ShenshaResult = {
  catalogVersion: "1";
  checkedCount: 43;
  matched: {
    ruleId: string;
    name: string;
    hits: ShenshaHit[];
    timing: {
      currentDecade: ShenshaHit[];
      currentYear: ShenshaHit[];
      nextYear: ShenshaHit[];
    };
  }[];
};
```

### 계산 원칙

1. 기존 `lib/saju`가 계산한 네 기둥을 입력으로 사용한다.
2. 각 규칙이 정한 기준 글자와 검색 대상을 그대로 대조한다.
3. 한 항목이 여러 위치에서 적중하면 항목을 복제하지 않고 `hits`에 모든 근거를 쌓는다.
4. 타고난 사주 계산과 시기 계산을 분리한다.
5. 현재 대운·올해·내년의 간지에서 같은 대상 조건이 나타나면 `이 시기에 같은 상징 조건이 다시 나타남`으로 기록한다.
6. 다시 나타났다는 사실만으로 강해짐, 사건 발생, 길흉 전환을 확정하지 않는다.
7. 발견 항목이 0개이면 오류로 처리하지 않고 `이 규칙집에서는 발견되지 않았어요`라고 표시한다.
8. 원본 생년월일·출생시간·성별은 결과 객체에 넣지 않는다.

- 규칙집 43개 검사 완료
- 발견된 귀인·도움 상징 수
- 발견된 주의·혼합 상징 수

### 항목별 카드

각 카드에 다음 내용을 모두 표시한다.

1. 이름과 쉬운 한 줄 뜻
2. 발견 위치와 계산 근거
3. 삶에서 연결해 볼 영역
4. 긍정적으로 나타날 수 있는 환경과 행동
5. 어렵게 나타날 수 있는 환경과 행동
6. 일상 속 가상 예시
7. 좋은 방향으로 활용할 작은 행동
8. 현재 대운·올해·내년에 같은 조건이 나타나는지
9. 계산법 차이 또는 출처 상태

`길`, `흉`, `대길`, `대흉`만 단독으로 표시하지 않는다. 사용자가 무서운 항목만 따로 모아 보도록 만들지 않는다.

## Gemini 역할과 결과 계약

- 앱이 계산한 `ShenshaResult`만 Gemini에 전달한다.
- Gemini는 항목의 존재 여부, 이름, 위치, 시기 적중을 새로 계산하거나 바꾸지 않는다.
- 발견된 모든 항목에 대해 빠짐없이 설명을 반환한다.
- 각 설명은 `쉬운 뜻`, `positiveConditions`, `challengingConditions`, `lifeExample`, `action`, `timingNote`, `evidenceRuleIds`를 포함한다.
- `positiveConditions`와 `challengingConditions`는 성격을 확정하지 않고 환경·선택·반복 행동의 조건으로 쓴다.
- 사고, 질병, 이별, 범죄, 재산 손실, 사망, 합격, 결혼을 예언하지 않는다.
- 성별 고정관념, 도덕적 평가, 공포를 유도하는 표현을 사용하지 않는다.
- 계산된 항목 수와 Gemini가 반환한 항목 수·ID가 일치하지 않으면 결과를 저장하거나 표시하지 않는다.

## 저장과 호환성

- 계산 결과에 `catalogVersion`을 저장한다.
- 로그인 사용자는 기존과 같이 가장 최근 정상 결과 1개만 저장한다.
- 기존 저장 결과에 `shensha`가 없어도 계속 표시한다.
- 새 결과는 신살 계산과 해석이 모두 정상일 때 함께 저장한다.
- 긴 결과가 저장 크기 제한을 넘지 않는지 테스트한다.

## 출처와 품질 기준

- 43개 분류의 초기 목록은 공개 구현의 목록과 규칙 자료를 비교해 만든다.
- 계산표는 최소 두 공개 자료가 일치하면 `cross_checked`로 기록한다.
- 고전 또는 공개 표 사이에 차이가 있으면 하나를 서비스 규칙으로 선택하고 `method_difference`로 표시한다.
- 일부 조건만 확인된 규칙은 `partial`로 표시하며, 고전 전체의 완전한 재현이라고 주장하지 않는다.
- 규칙 파일에는 항목별 참고 URL과 확인 날짜를 기록한다.
- 자동 테스트 통과를 전통 해석의 현실적 정확성이 증명된 것으로 표현하지 않는다.

## 실패와 예외

- 규칙 데이터가 잘못되었거나 알 수 없는 기준값이 있으면 해당 요청 전체를 중단한다.
- Gemini가 계산되지 않은 살·귀인을 추가하면 응답을 거부한다.
- Gemini가 발견된 항목을 누락하거나 근거 ID를 바꾸면 응답을 거부한다.
- Gemini 설명 생성에 실패해도 앱이 계산한 항목과 근거는 확인할 수 있게 한다.
- 실제 출생 자료를 외부 검증 사이트로 자동 전송하지 않는다.

## 구현 단계

1. 43개 규칙의 이름·별칭·계산표·출처 상태를 `shensha-rules` 데이터로 작성한다.
2. 규칙 엔진과 기준 사례 자동 테스트를 만든다.
3. 현재 대운·올해·내년의 재등장 계산을 추가한다.
4. 계산 근거를 먼저 화면에 표시한다.
5. Gemini 구조화 해석과 검증을 추가한다.
6. 저장 크기와 기존 결과 호환성을 확인한다.
7. 실제 화면에서 서로 다른 생년월일 기준 사례를 비교한다.

## 완료 조건

1. 모든 요청에서 규칙집 43개를 빠짐없이 검사한다.
2. 사용자에게 발견된 항목을 개수 제한 없이 모두 표시한다.
3. 같은 항목의 모든 발견 위치와 기준 글자를 확인할 수 있다.
4. 타고난 조건과 대운·올해·내년의 재등장을 구분한다.
5. 모든 항목에 좋은 방향과 어려운 방향, 예시와 행동이 함께 나온다.
6. 규칙 차이가 있는 항목에 서비스 기준과 차이 안내가 보인다.
7. Gemini가 계산을 바꾸거나 항목을 누락하면 결과를 거부한다.
8. 기존 결과 호환, 타입 검사, 자동 테스트, 빌드와 실제 화면 확인을 통과한다.

## 이번 Spec에서 제외

- 규칙집 밖 학파의 이름을 `전부 포함`한다고 주장하는 것.
- 살·귀인만으로 사주 전체나 실제 사건을 판정하는 것.
- 현재 연도의 12개월마다 43개 전체를 다시 계산하는 것. 첫 구현은 현재 대운·올해·내년까지 다룬다.
- 전문가 상담, 의료·법률·투자 판단을 대신하는 기능.
