# 사주 서비스 안정성 검증

## 완료 기준

핵심 흐름을 정상·오류·새로고침·모바일에서 확인하고, 재현된 미처리 오류를 수정한다. 자동 테스트·타입 검사·빌드가 통과하고, 운영 배포 뒤 실제 URL에서 주요 흐름과 `.env` 비노출을 다시 확인한다. 확인하지 못한 항목은 통과로 기록하지 않는다.

## 확인한 오류와 조치

- 계정 저장 결과를 읽는 중 브라우저 저장소 접근이 거부되면 처리되지 않은 예외가 날 수 있어, 로컬 대체 결과 읽기를 예외 처리했다.
- 공유 요청의 JSON이 깨졌을 때 서버 오류 대신 400으로 응답하고, 링크 생성 뒤 목록 갱신만 실패하면 생성된 주소를 유지해 직접 복사할 수 있게 했다.
- 자동 클립보드를 지원하지 않는 브라우저에서는 직접 복사 안내를 표시한다. 로그아웃 요청이 네트워크 오류로 reject해도 안내와 버튼 상태 복구를 수행한다.
- 실제 Gemini 응답의 한 문장이 6자, 재시도에서 7자로 생성되어 기존 8자 최소 기준에 막혔다. 짧은 한국어 문장도 유효할 수 있으므로 프롬프트에는 8자 이상을 권장하고 형식 검사는 6자부터 허용했다. 이후 동일한 시험용 입력의 생성이 성공했다. 5자 이하는 계속 거부하는 독립 회귀 테스트가 통과했다.
- 저장된 결과가 있는 상태에서 `/start`를 열면 이전 풀이 전체가 입력 폼 아래 다시 나왔다. 새 입력 전에는 풀이를 숨겼다. 빈 입력 뒤 나타나는 ‘최근 저장된 결과 다시 보기’ 버튼은 `/result`로 이동하도록 보완했다. 두 흐름을 375px 브라우저에서 확인했다.
- 계정 저장 실패 뒤 새로고침하면 서버가 정상적으로 빈 결과나 더 오래된 결과를 반환할 때 사용자별 브라우저 대체 결과가 무시됐다. 대체 결과가 더 최신이면 다시 표시하고 저장 재시도를 제공하도록 수정했다. 계정 저장 성공 또는 서버 결과가 같거나 더 최신이면 대체 저장을 지운다. 선택 경계 테스트 4개가 통과했으며 실제 로그인 브라우저 재현은 남아 있다.

## 운영 배포 상태

새 결과 페이지와 공유 기능은 아직 운영 서비스에 배포되지 않았다. 자동 승인 검토가 현재 작업 폴더 전체의 Production 배포에 명시적 승인 부족을 이유로 거절했다. 이 승인을 받기 전에는 운영 배포를 다시 시도하지 않는다. Supabase 공유 테이블 마이그레이션은 적용되었지만 기존 운영 화면에는 새 기능이 보이지 않는다.
